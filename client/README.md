# Slurmate 桌面客户端

把集群上的**作业**包装成桌面应用。作业里跑什么由**插件**决定。

★ **基座自己不带任何插件** —— 一个都没有是正常状态。`src/main/plugins/` 那个目录
是**框架**（注册表 + 铸造 id 的 `ulid.js`），不是插件目录。插件只有**一条来路**：
站点分发 —— 连上站点之后自动取回来，落在 `~/.slurmate/site-plugins/`，而池里
每一份都过同意闸。仓库顶层的 [`plugins/`](../plugins/) 下有两个现成的，
**开发者模式**用的就是它们（见下面〈开发者模式〉那一节）。

界面上的「开始会话」那一块是**按插件画出来的**（池里扫出几个就画几个），一个插件名
都没写死 —— 所以卸掉一个插件，那一块就不见了，而不是"点了报错"；而一个都没有时，
那一屏给的是一条**去向**（连上站点去取），不是"安装包可能不完整"。

**插件的源码树是一个目录**（而**分发**出去的是它打成的那个包 —— 见
[`packer/`](../packer/)）：

```
<插件目录>/
  plugin.json        身份（铸造出来的 `id`）、版本、以及框架会读的那几条声明
  client/index.js    客户端侧代码 —— 可有可无，没有它就是一个纯声明式插件
  job/start.sh       作业侧代码 —— **客户端不看它**，由站点的部署脚本为它织一份
                     `<prefix>/share/slurmate/jobs/<ULID>.sbatch`（一个插件一份）
```

★ 客户端池里存的仍然是一棵**解出来的树**（站点把整个包发下来，客户端把它解开），
所以下面讲的都不受"包"这件事影响。

`plugin.json` 里的 `id` 是一个 **ULID**（`ulid.js` 铸的，26 字符），**诞生时铸一次、
此后永不改变** —— 它不是名字。有了它，同一个插件被两个站点分发时能被认出来是
同一个（池里合并成一条），而两个站点各写一个同名插件时又能被分开（两个 `id`、
池里两条）。站点的短名（`name`）只管本站内可读，可以随时改。

> ★ 这里从前还跟着一句"各自标明来源"，而界面上**今天不显示来源** —— 客户端只剩
> 一个池、来源数恒为一之后，那个标签恒为 `null`，所以连字段带渲染一起删掉了。
> ★ **"哪个站点要哪一版"这件事本身还在**，只是它不进界面：对账要靠它算引用计数，
> 而那份账在池根的 `.sites.json` 里（形状不在规范里，见 PLUGIN-SPEC 的附录 B）。

**装与卸都在一处**：[`src/main/site-plugins.js`](src/main/site-plugins.js) ——
对账（站点说了算）、按引用计数回收不再被任何站点要的版本、换入前过同意闸。
`src/main/plugins/` 里只有**框架**（注册表 + `ulid.js`），没有一个"装"的动词。

> ★ **这里从前还有一个根、一个安装器。** `~/.slurmate/plugins/` 是"本机池"，
> 用户可以自己挑一个 `.splug` 装进去、或者干脆**拷一个插件目录进去**，而那一整类
> **不过同意闸**（`allows` 里写着 `entry.source !== 'site' || …`）。而
> `docs/PLUGIN-SPEC.md` §5.2 明文写着「**禁止**给任何一类插件开免同意的口子」，
> §5.1 要「往池目录里手工放置内容**必须**不产生任何效果」—— **规范与代码正面相反，
> 而两边都没有红过，因为没有任何一条用例去验规范那两句。**
>
> 所以 v0.7 不是"给那条路补一道闸"，是**让那一类插件不存在**：装与卸只剩站点分发
> 这一个动作，`src/main/plugins/install.js` 整个文件删掉，那个"两个根不是洁癖"
> 的论证（回收只该删站点拥有的那些）随之失去对象。★ 那个论证本身仍然成立，
> 只是今天只有一个根，用不上它。

### 站点分发：谁在什么时候做什么

```
连上站点 ──► 对账（site-plugins.js）
               │  1. 问清单（plugins）—— 顶层没有 limits ⇒ 站点太旧，到此为止
               │  2. 问 list，把活会话用着的版本收进保护集（这一次不回收它们）
               │  3. 取锁 → 清暂存 → 读记录（.sites.json）
               │  4. 逐插件：
               │       · 池里没有它，而台账信任它 ⇒ **撤回同意**（§5.3），重新问
               │       · 已有一份且对得上、台账也相符 ⇒ 跳过
               │       · 已有一份、台账**对不上** ⇒ 暂存指向**已存在的那棵树**，
               │         进【同意闸】（这就是那个"看不见的洞"的修法）
               │       · 已有一份、内容对不上 ⇒ 明确失败，**绝不覆盖**
               │       · 都没有 ⇒ 取回暂存（整包一次取）→ 校验 →
               │         【同意闸】→ 换入（树与包一起）
               │  5. 写记录（在回收之前 —— 唯一会真丢数据的地方）
               │  6. 回收：没有任何站点要、也没有活会话用 ⇒ 删（树与包一起）
               └─ 7. reload() 之后**逐个复查 registry.get(id, 版本)**
```

**一条投递方式**：`plugin_package`（一条 RPC 取回整个 `.splug`，能自己解析、
自己重算摘要、自己验签）。★ v0.6 时还有一条退路（`files` + `plugin_file` 一份文件
一次），**v0.7 删掉了** —— 它发的是散装字节、证不了签名者，留着它就是留一条**验签
绕得过去**的路。代价是"包格式比客户端新"从"退回逐份取"变成一条**明确的失败**。

六条纪律，每条都对应一种"系统说成了、事情没成"：

1. **绝不谎报成功** —— 任何一份字节没到手或对不上，这次分发就报失败；报成功时，
   磁盘上的内容按字节就是站点那一份。
2. **判据是能力缺席，不是这次失败** —— "站点不支持分发"只看 `plugins` 响应的
   **顶层有没有 `limits`**。拿"下载失败"当判据，等于给一个能让下载失败的人（断流、
   丢包、中间人）一个把用户降级到旧本地副本的开关。
3. **不知道谁在引用时，什么都不删** —— 记录读不出来 ⇒ 只报告、不回收。与
   `deploy.sh` 的「有东西但没有标记 ⇒ `die`，不删」同一个先例。
4. **同意闸在"下载后、暂存验完、换入之前"** —— 更早没有摘要可同意（摘要是从字节
   算出来的），更晚就已经执行了（`activatePlugin()` 里那个 `require()` 就是执行）。
5. **删除 = 撤回同意**（§5.3）—— 池里那一份不在了 ⇒ 台账那条一并消失 ⇒ 下一次
   **重新问**。不这么算的话，"删掉"会被下一次对账读成"摘要与台账相符"而**静默装
   回来** —— 那不是"当作从来没有过"，那是"用户想让它消失，它自己回来了"。
6. **签名者必须是同一把钥匙**（§5.4）—— 第一次同意一个签过名的构件时钉住它的
   公钥，此后每一份都必须相符。★ v0.6 时逐份那条路也判（它发的是散装字节、证不了
   签名者，所以钉过的 id 在那里一律拒）—— 而 **v0.7 把那条路删掉了**，所以那个
   缺口关在了**结构**里，不再靠一句判断挡着。

★ 这六条各自都有能真的红的用例，在 `test/site-plugins.test.mjs`（以及
`boot.test.mjs` 里端到端的那几条）。

解决五件事：

1. **浏览器抢快捷键** —— Ctrl+W 不会再关掉页面
2. **端口靠用户自己拟** —— 服务端口由集群侧自动分配
3. **多开打架** —— 一个窗口里可以同时活着**几个**会话，各占各的端口与存储
4. **SSH 闪断杀死会话** —— 作业挂在 Slurm 上而不是 SSH 会话上，断线不掉
5. **首次连接摩擦** —— 客户端自己生成密钥，公钥复制到账户里即可

## 认证：只用公钥，客户端自托管密钥

客户端**不接受密码**，也**不读你的 `~/.ssh`**。

**密钥是每条连接一把的。** 点开「新建连接」时客户端就生成好一把**专用** ed25519
密钥，你在表单里看到、复制、加进自己的账户，然后再填地址 —— 两步各自有明确的去处。
之后这条连接在列表里带一个「编辑」，随时能看到自己的那把公钥、也能单独作废重来。

为什么按连接而不是全局一把：公钥是注册在**某个账户**上的，而一条连接就是
「哪个账户、哪台机器、哪个端口」。按连接存，重新生成一把钥匙才只作废那一条，
不会顺带把别的连接打断。

私钥**永远加密保存**（系统凭据库），没有第二个选项。机器上没有凭据库时不静默写明文，
也不问你要不要明文保存 —— 而是如实告诉你这把密钥存不下来、下次启动会换一把新的。
而「读不出来」（换机器、凭据库被重置）时**绝不自动覆盖**：那会作废你已经注册过的
公钥，而症状只是「认证失败」，指不回根因 —— 这种情况会明确报错，由你决定。

这样做而不是复用你已有的 SSH 密钥，有两个理由：那把密钥通常能登所有机器，
权限过大；而且它的生命周期归你管，你换机器或删密钥时，客户端会毫无征兆地失效，
报错只会说「认证失败」。

私钥存在哪、怎么加密、`safeStorage` 不可用时怎么办，见 `src/main/keys.js` 与
`src/main/config.js` 的文件头。

**认证被拒时，客户端会把「用的是哪把钥匙」一并报出来**：`All configured authentication
methods failed` 是 ssh2 的原话，唯一含义是服务器不认这把公钥，但它一个字都不提你用
的是哪把。所以那一条错误里带着指纹和公钥原文，以及一条能自己跑的核对命令。

**主机密钥是 TOFU 校验的**，不是不校验：第一次连一台主机时客户端会**拒绝**并把
指纹交给你核对；指纹**变了**则永远拒绝（不是警告）。ssh2 默认不校验主机密钥，
不做这件事的话，「只走公钥认证」会退化成一个不校验身份的加密连接 —— 比口令认证更糟。

## 开发者模式

界面底部有「开发者模式」那一节：勾上开关、点「立即重启」。**没有命令行参数** ——
这是一个图形应用，而 Windows 用户没有地方输入参数；而且那会给人一种"必须在安装时
选好"的感觉。

开关**重启后生效**（换后端要重建整个客户端），界面会明说这一点，不静默地半生效。
打开之后：

- 客户端**不连集群**，改用**假后端**（`backend-fake.js`）；
- 数据落在 `<userData>/dev-sandbox/`，**绝不会碰你自己那份配置**；
- ★ 但里面的东西**会留着**（连接、密钥、插件、同意台账）—— 它是给插件作者与改
  客户端的人用的**沙盒**，不是一个临时的演示。关掉开关不会删掉它。

**假后端的两个身份，别搞混：**

| 身份 | 是什么 |
|---|---|
| ① 不连集群时能看到完整界面 | 上面说的那个沙盒。界面、状态条与窗口标题会标注「开发者模式 · 未连接集群」 |
| ② **客户端 app 级测试的后端** | `test/boot.test.mjs`、`integration.mjs`、`contract.mjs` 全都跑在它上面 —— 没有它，这一层的测试只能去连一个真集群。选它的方式是**写那个设置文件**（`dev-mode.json`），也就是用户点开关走的同一条路 |

**插件作者的那条轻路径**：同一节里可以把「假站点的插件来源」指到**你自己那棵插件
树**（默认是仓库里的 `plugins/`）。选完它会当场报"读到几个插件"—— 选错了的症状是
"重启之后假站点一个插件都不报"，而那句话指不回原因。来源与真的守护进程一样是
**启动时的快照**，所以换了目录也要重启。

假后端**不是空壳**：它包含一个真的本地 HTTP 服务，按**当前会话那个插件声明的
登录契约**（`contributes.login`）提供页面与表单，并且真的走一遍隧道代码。
**那个假服务是通用的** —— 端点、字段名、cookie 名全部来自清单，它里面没有任何一个
具体网页服务的名字。所以下面这些路径是真的在跑：

- 会话状态机（提交 → 排队 → 登记 → 运行 → 释放）
- 本地端口绑定与占用顺移（顺移**只影响这一次**会话，不写回配置）
- 隧道中继（真的 TCP 转发，真的只监听 127.0.0.1）
- 登录契约（`POST <清单里的路径>` + cookie jar 判定）
- 快捷键接管与诊断

**唯一被假掉的是 SSH 那一跳。**

## 跑起来

```bash
npm install
npm start          # 真实后端；还没配连接时会提示去填
npm test           # 全部测试，不需要 Electron 运行时

# 开发者模式（不连集群、也不碰你真配置）在**界面里**开：底部的「开发者模式」
# 那一节 → 勾上 → 「立即重启」。没有对应的命令行参数 —— 见上面那一节。
```

`npm install` 会下载 Electron 二进制（约 100–150 MB）。国内网络慢的话可以先设镜像：

```bash
npm config set ELECTRON_MIRROR https://npmmirror.com/mirrors/electron/
```

> **不要把 `node_modules/` 放在网络共享盘上**（比如 NAS 的 SMB 挂载）。
> 文件多且路径长，Windows 上会非常慢甚至失败。请把仓库克隆到本地磁盘再 `npm install`。

> ⚠️ **`npm test` 里的 `node --test` 不能加路径参数。**
> Node 18 容忍 `node --test test/`（把目录当扫描起点），**Node 22 不再容忍** ——
> 它会把这个参数当成 glob 模式，解析不到就报 `Cannot find module .../test`。
> 而 CI 用的是 Node 22，本地是 18，所以这行在本地永远测不出问题。
> 不带参数时靠的是官方默认模式 `**/test/**/*.{cjs,mjs,js}`，18 和 22 都支持，
> 且会自动排除 `node_modules/`。

### 怎么验证快捷键接管

开发者模式下启动一个会话，会打到一个**按键回显页**：

| 按什么 | 期望 |
|---|---|
| `Ctrl+W` | **出现在左栏**（到达页面 —— 在外壳这一侧这就够了，那个键该怎么用是插件的事） |
| `Ctrl+N` / `F5` | **出现在左栏** |
| `Ctrl+Shift+I` / `F12` / `F11` | **出现在右栏**（被外壳吞掉，不打开开发者工具/全屏） |
| 中文输入法打拼音 | **两栏都不出现**（组合期间必须放行给输入法，否则输入法会被吃掉） |

左右两栏对照就是判定依据。

### 调试开关

开发者模式下面板底部有一组开关，用来造出真集群上极难复现的状态：

- **模拟守护进程挂掉** —— 验证客户端**不会**因此判定会话结束
- **模拟隧道断开** —— 验证遮罩出现、重连提示、恢复后焦点回到编辑器
- **模拟会话被回收** —— 验证「作业被 scancel 了」这条路径
- **站点不支持分发**（`old-distribute`）—— 让假后端报插件但**不报顶层 `limits`**。
  回退必须是那一句「本站的守护进程太旧」，而**不是**退回池里已经有的那一份
- **插件太大**（`plugin-too-big`）—— 往某一份的**包里**塞一个超过单文件上限的文件，
  验证客户端**拒绝**而不是截断
- **站点在限流**（`rate-limited`）—— 让假后端先回几次 `7 rate_limited`，验证客户端
  **退避重试**，而不是把它报成"同步失败"
- **站点有个本机没有的插件**（`extra-plugin`）—— 「站点有而本机没有 ⇒ 升级客户端」
  那条提示的唯一来源
- **复位**

> ★ 还有几个动作只有 IPC 没有按钮 —— `old-daemon` / `site-plugin-off` /
> `site-plugin-no-job` / `daemon-version`（后三个可以带参数），在 DevTools 里
> `window.slurmate.debug('old-daemon')`、`window.slurmate.debug('daemon-version', '2.5')`。
> **它们造的是不同的状态**（老守护进程那条会退回池里已有的那一份，站点关掉那个**不**退；
> `daemon-version` 造的是版本握手那两态里真机上造不出来的：站点比客户端新、
> 以及两个大版本之间），别把那几个混着用。

## 打包

```bash
npx electron-builder --publish never
```

产物在 `dist/`。三平台配置见 `electron-builder.yml`。

CI 在**仓库根目录**的 `.github/workflows/build.yml` —— 不是本目录。
（GitHub Actions 只读仓库根的 `.github/workflows/`，放在 `client/` 下永远不会被触发。）
workflow 里所有步骤都带 `working-directory: client`，推 `v*` tag 会把三平台产物挂到

### 四条不要改坏的约束

改动 `src/main/` 时，下面每一条都对应一个具体的、在真实环境里表现为「一切正常但就是没保护」的故障：

1. **隧道目标只从 `tunnel_target` 解析，且必须是字面 IPv4。**
   禁止重新解析节点名 —— 解析结果与集群侧写进 nft 规则的 `ip daddr` 不一致时，
   ACL 会静默失效。见 `tunnel.js` 的 `parseTarget`。

2. **登录成败只看 cookie jar，不看 HTTP 状态码。**
   网页表单登录这一类协议里，口令错误时返回 **200** 且没有 `Set-Cookie` 是常见形态
   （code-server 4.135.0 实测如此）。`if (status === 200)` 会在口令错时报成功。
   见 `weblogin.js`。

3. **`goodbye` 返回 `ok:true` 不代表作业被取消了。**
   集群侧的 `op_goodbye` 丢弃了 `scancel` 的返回值，`phase_release` 也不确认作业是否
   真的没了（编号 F12 / F13，见 [`docs/KNOWN-ISSUES.md`](../docs/KNOWN-ISSUES.md)）。
   所以界面把「正在释放」和「已结束」当成两个状态。见 `session.js` 的 `stop()`。
   **这一条对应的缺陷还没修** —— 客户端这边的两个状态是它的应对，不是它的修复。

4. **激活就是 `require()`，所以它必须是两趟。**
   `plugins/index.js` 的 `activatePlugin()` 在读到 `client/index.js` 时会**当场**
   `delete require.cache[…]; require(clientPath)` —— **激活就是执行**。因此任何
   "先全都扫进来、之后再决定哪些激活"的写法都会让**同意闸形同虚设**：远端代码在
   用户看到对话框之前就已经在主进程里跑完了，点"不同意"什么也拦不住。
   所以扫描与激活是两个函数（`inspectDir()` / `activatePlugin()`），而
   `Registry` 那道 `allows` 谓词问的是**每一个**目录、没有例外。
   用例在 `test/boot.test.mjs`：一个在被加载时写标记文件的插件，**在对账跑完、
   点同意之前**，那个标记文件必须不存在。这一条改坏了，症状是"一切正常"——
   界面照常问你要不要同意，而代码早就跑过了。

## 集群侧契约（客户端依赖的部分）

`slurmate rpc`：从 stdin 读一行 JSON，向 stdout 写一行 JSON，然后退出。**一次一请求。**

```
ssh -T -p 10100 user@<登录节点> -- "/bin/bash -c '/usr/local/bin/slurmate rpc'"
```

外层双引号是必须的：本地 shell 会先把单引号吃掉，去掉它就变成另一个命令串，
验的就不是客户端真正发的那个了。

请求体走 stdin，所以命令行是编译期常量 —— 这既是防注入，也是穿过登录节点上
`codeserver-guard`（`ForceCommand`）的必要条件：命令串里不能出现 `code-server` 字面量。

**为什么显式包一层 `/bin/bash -c`**：sshd 执行 exec 请求用的是登录 shell
（`$SHELL -c "…"`，值来自 /etc/passwd，HPC 上常是 zsh）。把解释器钉死成 bash，
就不会出现「这条命令串在 zsh 下是语法错误、换台机器就好」这类查不出原因的问题。
**但它挡不住 rc 文件**：sshd 仍先用登录 shell 解析整个串，所以 zsh 的 `~/.zshenv`
（连 `-c` 都会读，bash 不会）照样会执行；它若往 stdout 打印东西，就混进了应答。
客户端对这种情况的防线在解析侧 —— 从后往前找第一个带布尔 `ok` 的 JSON 对象，
并在失败时把原始输出报出来。所以**用户不需要为此保持 `~/.zshenv` 安静**，
但看到「返回 N 行输出，都不是协议应答」时，第一个该查的就是它。

响应形如 `{"ok":…, "code":…, "data":{…}, "error":{"kind":…,"detail":…}}`，错误码：
`2` 客户端 bug / `3` 会话不存在 / `4` 配额权限 / `5` 守护进程不可达或端口池空 /
`6` Slurm 失败 / `7` 限流 / `9` 内部异常。

> **`code:5` 有两种含义，必须靠 `error.kind` 区分**：`daemon_unreachable` 是
> 「守护进程挂了」（要重试，且绝不能判定会话结束），`no_port` 是「端口池满了」（等一下）。
> 见 `classify.js`。

心跳：客户端经 unix socket 定期发 `heartbeat`。守护进程判活**只看这个**，
不读作业写的 `.jobhb` 文件。停发 300 秒判定 `suspect`，1800 秒判定 `orphaned` 并 scancel。
