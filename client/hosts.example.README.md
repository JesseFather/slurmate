# `hosts.example.json` 说明

## 这个文件不会被程序读取

`hosts.example.json` **只是一份格式模板**。客户端不会去读它，放在这里也不会改变
任何行为 —— 它旁边的 `hosts.example.README.md`（也就是本文件）和它是同一个东西：
给人看的文档。

**真实地址要填在客户端的「设置 → 登录节点地址」里**，由客户端存进本地配置的
`extraHosts` 字段。真正的配置文件和这个模板不在同一个位置，也不会被提交进仓库。

> 为什么不直接改这个文件？
> 因为配置里**没有内置地址**（`src/main/hosts.js` 的 `BUILTIN_HOSTS` 是有意为空的）。
> 每个部署的登录节点都不一样，把地址写进源码等于把某个站点的网络拓扑发布出去，
> 而且别人 fork 走之后只会连到一个不属于他的集群。所以地址只能由使用者自己填。

## 字段

数组里每一项的形状：

| 字段 | 类型 | 说明 |
|---|---|---|
| `host` | string | **必填。** 登录节点的 IPv4 地址或域名 |
| `port` | number | **必填。** 该节点的 SSH 端口。Slurmate 的部署默认是 `10100` |
| `label` | string | 选填。界面和诊断信息里显示的名字。留空时回落到 `host` 本身 |
| `priority` | number | 选填。数字**越小越先试**。省略时按它在数组里的下标排（1 起） |

上例里的地址全部是文档保留地址（RFC 5737 的 `192.0.2.0/24`、`198.51.100.0/24`、
`203.0.113.0/24` 与 RFC 2606 的 `example.com`），**直接抄过来是连不通的**，必须换成
你自己的登录节点地址。

## 为什么要填多个地址

同一个登录节点常常有多个入口：内网地址、内网备用地址、公网域名、跳板机映射。
只写一个的后果是换个网络环境就连不上，而用户看到的只有一句「连接失败」。

客户端会**并发探测全部地址**，按 `priority` 取第一个可达的。全部不可达时，
每个地址各自的失败原因都会报出来 —— 而不是一句笼统的错误。

## 探测怎么判定「可达」

TCP 连上之后**读 SSH banner**（`SSH-2.0-...`），而不是只做一次 TCP connect。

只连不读的话，任何在这个端口上监听的东西都会被判成「登录节点可达」—— 一个端口转发
中间盒、一个 REJECT-then-accept 的防火墙，都会给出假绿：检查确实执行了、也确实通过
了，但通过的原因和它想证明的事毫无关系。

所以：**地址填对了，但对面不是 SSH 服务，客户端不会用它。** 这是有意的。
